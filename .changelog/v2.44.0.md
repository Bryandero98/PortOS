# Release v2.44.0

Released: 2026-08-16

## Highlights

- **Video creation:** MiniMax H3 can now generate video with audio on supported NVIDIA Windows systems, while Video Gen adds swappable text encoders, LTX-2.5 options, and one-click remix from past renders.
- **Music and SongBook:** Music Studio gains a guided song designer plus ACE-Step 1.5 and MiniMax Music 3 support, while SongBook adds play-along, timed autoscroll, linked records, and spaced-repetition practice.
- **Mood boards and universes:** Build boards from gallery media, analyze items with AI, and turn a universe's linked mood board into an editable visual style guide.
- **Story and creative workflows:** Universe-bible entries can be described before rendering, and editorial and Autopilot work now show clearer progress while completing faster.
- **Local AI choice:** New MTPLX presets, clearer local-model recommendations, configurable reasoning effort, and more efficient Ollama discovery make local providers easier to select and operate.
- **Chief of Staff automation:** Agents can carry a task through their own review and pull-request loop, with a persistent milestone map and more reliable task/worktree recovery.
- **Accessibility and mobile:** Broad form-labeling improvements and stronger accessibility checks make more of PortOS usable with screen readers, touch, and small screens.
- **Windows reliability:** Background tools no longer flash consoles or steal focus, and installers, updates, agent supervision, and worktree handling are substantially more reliable on Windows.
- **Media and runtime resilience:** Local generation jobs coordinate accelerator access, model downloads report real progress, and broken runtime installs recover with clearer next steps.
- **Data integrity and navigation:** Activity dates respect the selected timezone, unreadable data is no longer mistaken for empty data, and more views retain shareable deep links.

The macOS list has had H3 since #242, but it runs on PipeNetwork's Apple-Silicon MLX port, so an NVIDIA box had no H3 path at all — the Windows video catalog held exactly one model (LTX-Video 0.9.5). A new `minimax_h3_cuda` BYOV runtime (`~/.portos/minimax-h3-cuda`, installed from Video Gen or `INSTALL_MINIMAX_H3_CUDA=1 bash scripts/setup-image-video.sh`) plus a `MiniMax H3 CUDA int8` model entry bring the same joint video+audio model, the same 768px 32-aligned canvas, the same fl2va first/last keyframe anchoring and the same license gate to the Windows list. ## Fixed

- Arc-verify telemetry now reports every resolver attempt with what it actually wrote — per-record mutation counts plus a categorical reason when nothing changed — so a spine round's edits are no longer invisible behind episodesEdited: 0
- Arc verification no longer stalls on a truncated character-arc milestone: over-cap transition labels now end on a complete clause, and the arc-resolve prompt receives the per-character and per-transition field budgets it was previously writing blind against

- A merge follow-up now takes over the worktree that already holds its PR branch instead of blocking on it
- `scripts/setup-image-video.sh` runs its mflux + FLUX.2 preamble again on a bare invocation. The "was any BYOV runtime requested?" check concatenated ten `INSTALL_*` defaults and compared the result to a literal eight-zero string, so it never matched — every bare `bash scripts/setup-image-video.sh` took the BYOV-only branch and silently skipped the image-gen setup it advertises. It now tests for any non-zero character, which cannot drift as runtimes are added.
- Migration 242 no longer suppresses video models added to the catalog after it shipped. Its `_shippedDefaults` bootstrap unioned the user's model ids with **today's** `data.reference/media-models.json`, so on a registry that predated the snapshot key it recorded every current built-in as already-delivered — including entries added long after 242 was written. `appendNewlyShippedEntries` reads a recorded id as "the user deleted this", so those entries were then permanently hidden on exactly the installs that had never seen them, with no later migration able to tell the difference. The bootstrap now unions against the id set pinned in the migration itself.
- HuggingFace LoRA install now detects Flux.2 Klein (and other image families) instead of only offering LTX-Video.
- Windows: the in-app runtime installers (Video Gen BYOV runtimes incl. MiniMax H3 CUDA, the music engines, the MuScriptor MIDI venv) and app `deploy.sh` runs now go through Git Bash instead of a bare `bash` that PM2 often resolves to WSL. The installer also gets a script path bash can open, a `PYTHON_BIN` that isn't the WindowsApps Store stub, and a cancel that takes uv / pip / git down with it.
- **Windows console windows no longer flash and steal focus.** A process with no console of its own — every PortOS app, since they are all PM2 forks — makes Windows allocate a brand-new console for any console child it spawns (`git`, `gh`, `psql`, `ffmpeg`, `where`, `taskkill`). Under the Windows 11 default terminal setting that allocation is handed to Windows Terminal over COM, which starts `OpenConsole.exe -Embedding` plus a terminal window that grabs foreground focus and dies with the child; at PortOS's background spawn rate that is a steady stream of unusable windows stealing keystrokes. Server runtime code now imports `server/lib/childProcess.js` instead of `child_process` — a drop-in wrapper that defaults `windowsHide: true` (`CREATE_NO_WINDOW`) on every `spawn`/`spawnSync`/`fork`/`exec`/`execSync`/`execFile`/`execFileSync`, keeping `promisify.custom` so `promisify(execFile)` still resolves to `{ stdout, stderr }`, and honoring an explicit `windowsHide: false`. 84 files migrated. `childProcess.guards.test.js` now fails the build on a direct `child_process` import, on an aiToolkit spawn without inline `windowsHide`, and on `pm2` invoked through a shell — the same bug was swept away by hand in v1.5.x and v1.6.7 and regressed both times. Also routed the two `shell: true` pm2 calls back through `execPm2` (`cosHealthMonitor.js` auto-restart, `browserService.js` start/stop/restart/jlist/logs), dropping the `cmd.exe -> pm2.cmd -> node` hops and the PATH ambiguity of resolving a bare `pm2` through a shell, and fixed the missing `windowsHide` on the aiToolkit CLI probes and on `browser/server.js`. New `npm run fix:windows-console` points the machine's default terminal at the classic console host, which stops the handoff for every app on the box, not just PortOS. Background: `docs/WINDOWS_CONSOLE.md`.
