- An app's Submodules tab (and other views that send a repo path to the server) no longer fails with "path is outside allowed directories" when the repo lives on a secondary volume. The allowed-workspace-root defaults were POSIX-only, so a Windows repo on a drive other than C: matched nothing, and a Linux repo under /mnt or /media did the same. Defaults now cover /mnt and /media alongside /Volumes, and on Windows they are your home directory, the temp directory, and any lettered non-system drive (C:\Windows and C:\Program Files stay off-limits). PORTOS_WORKSPACE_ROOTS is also split on ";" on Windows, so a value like D:\repos;E:\projects is no longer cut apart at the drive letter.
