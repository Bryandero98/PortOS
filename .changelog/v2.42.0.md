# Release v2.42.0

Released: 2026-08-12

## Highlights

- **Series Autopilot's repair loop got much smarter about what to keep.** When an editorial fix improves one thing but not another, or a fix accidentally breaks something else, the system now salvages the parts that worked instead of throwing the whole rewrite away — for both story-arc repairs and foundation (world/character/structure) repairs. It also learns from run history which model/provider combinations actually produce keepers, remembers what it already tried and rejected so it doesn't repeat the same bad edit, and lets individual pipeline steps be routed to specialist models.
- **Character-first planning now covers the cast's visual identity, not just personality.** Physical description, silhouette, palette, and visual grammar are generated, tracked, and repaired alongside psychology and relationships, so a graphic-novel series doesn't have to invent character looks after the plot is already locked in.
- **Autopilot runs are safer to pause, stop, and resume.** A graceful Pause now lets in-flight work finish instead of killing it mid-step; stopping a run (or the app restarting mid-run) no longer gets misreported as a crash and no longer files a bogus bug report.
- **The local-model install catalog was refreshed to the current model landscape** (Qwen3.5/3.6, Gemma 4, GLM-4.7, Granite 4.1, and more), with superseded models retired and capability detection (tool use, vision) updated to match.
- **3D model generation gained two new automated checks**: one that catches parts modeled inside each other (a limb rooted inside a torso, a greeble swallowed by its hull), and one that flags materials whose physical properties don't match what they're named for (metallic wood, non-transmissive glass).
- **Video generation picked up several fixes**: continuing or extending a clip now carries its original prompt forward, LoRAs in an incompatible file layout are refused with a clear reason instead of silently rendering without effect, stitched/re-encoded renders now carry correct color tags so they stop looking washed out, and local renders show a time estimate once your machine has rendered something comparable.
- **A round of mobile and small-screen fixes** across Insights, Backup settings, System Health, Tribe, OpenClaw, the Digital Twin's now-grouped 19-section navigation, and the global update/out-of-sync notices — several of which were pinning key controls below the fold or on top of the screen entirely.
- **PortOS now works out of the box with no route to the public internet.** Both UI fonts are vendored and bundled instead of fetched from Google Fonts, fixing a ~60-second blank white page on any install without outbound internet access (the documented private-Tailscale deployment).
- **Background task reliability improved**: branch reconciliation now sweeps and reports orphaned remote branches and caches its verdicts instead of re-deriving them every cycle, a failed CoS task now investigates itself and automatically retries once the cause is fixed, and tasks routed through a temporarily unreachable CoS runner now hold and retry instead of burning through their retry budget or paging a human.
- **A handful of state-corruption and correctness fixes**: an unset render seed no longer silently pins every render to the same image, an over-long character-arc field no longer breaks saving the entire Series settings page, and several prompt-drift/migration bugs that were turning `main`'s CI red are fixed.

## Changed

- **Branch reconciliation now notices the branches its own cleanup leaves on the remote.** Deleting a merged local branch never touched `origin`, so every reaped branch left a remote counterpart behind that nothing local pointed at and nothing ever looked at again. Reconcile now sweeps the remote each cycle and reports those orphans, judging each one against the SHA the remote reports right now rather than a remote-tracking ref that may be arbitrarily out of date. Deletion stays opt-in and off by default: pushing a branch deletion reaches a shared forge and can't be undone locally, so an unattended cycle reports and leaves everything in place. Peer safety comes from the branch's state rather than its owner — a branch is only ever deletable once the default branch already contains its work, so no machine can lose anything, and an unmerged remote-only branch (which is what a federated peer's in-progress work looks like from here) is reported and never touched. A remote that can't be read, a local branch list that can't be read, and a commit this clone has never fetched all fail closed to report-only rather than guessing.
- **Branch reconciliation stops re-deriving the same superseded verdict forever.** A branch whose work already landed on the default branch under different file and function names is correctly left untouched — merging it would regress shipped code — but nothing ever reaped it either: git can't see it as merged, so it stayed in-flight and every recheck paid a full agent run to reach the identical conclusion. Two abandoned worktrees in one install were analyzed sixteen times that way. A coordinator that concludes SUPERSEDED now records the verdict — the branch tip, its uncommitted change set, the collision paths it judged against, and the commits on the default branch that replaced it — and later passes skip the analysis while all of that still holds. The branch is still reported, in its own "awaiting reap" section with the replacing commits and the exact removal commands, and nothing is ever auto-deleted. The cache expires the moment the judgment could change: the branch tip moves, its uncommitted files change, its collision set grows, or the commit that superseded it is reverted off the default branch. A missing or malformed ledger falls back to full analysis rather than hiding a branch that still needs work.
- **Daily Log no longer parks autosave when voice dictation lands mid-edit.** A spoken segment is merged into the textarea (append-at-end, caret restored) instead of leaving the user to Save or refresh, and full-content saves send the last-seen `updatedAt` as `ifMatchUpdatedAt`. When a concurrent append advances that clock, the server returns 409 `STALE_JOURNAL` with the current entry in `context.entry`; the client folds in any missing voice segments and retries a few times so an in-flight PUT cannot silently drop dictation.
- **Series Autopilot can learn which models actually work at each step.** AI run history now distinguishes technical completion from a later editorial keep/revert decision and aggregates evidence by orchestration step, creative-versus-judge role, provider, model, and reasoning effort. The new opt-in selector requires multiple quality-reviewed samples plus a positive reliability threshold, ignores disabled providers and removed models, and remains a soft default beneath explicit run choices and exact prompt-stage pins. The Options panel reports how much attributed and quality-reviewed evidence exists, while local APIs expose the full metrics and allow an operator to correct or backfill a historical outcome, including its effort when the older run predates effort telemetry. Concurrent metadata updates for one run are serialized so provider telemetry cannot overwrite its Autopilot step/role attribution, and internal structure-verification calls retain the judge role instead of inheriting their repairer's creative role. Foundation judges record contract-valid responses separately from true editorial approval, and foundation repairs automatically record accepted versus rolled-back outcomes. Arc repairs now do the same after normal rounds, corrective retries, and isolated-finding attempts, while canceled candidates remain deliberately unevaluated, so a model that finishes a long run but makes the story worse is not learned as a success.
- **Series Autopilot can route individual steps to specialist models.** A run may now override provider, model, and reasoning effort for the creative or judge role of one named orchestration step, from either the start API or the Options panel. Stage routes survive pause/resume, take precedence over learned and run-wide choices, and remain soft defaults beneath exact prompt-stage pins, so a weak foundation repair model can be replaced without repointing episode drafting or independent verification.
- **A reverted foundation repair now gets another attempt instead of ending the run.** A repair whose independent re-judge showed no gain for the dimension it targeted was correctly rolled back to its pre-repair checkpoint — and then treated as terminal, so a run configured for twelve foundation rounds paused after a single rejected attempt. The gate now retries that dimension from the verified checkpoint, telling the next attempt what was reverted and what the rejected re-judge still reported so it can change strategy, and reusing the rewound verdict rather than paying for an identical re-judge. Retries stay budget- and cancellation-gated, count against both the round limit and the existing per-dimension stall patience, and never retain an unvalidated edit; a rollback that fails its own checkpoint verification still stops immediately.
- **Foundation structure repair retains shrinking corrective progress.** A broad structure rewrite whose specialized arc verification improved from many blockers to a smaller residual used to get one correction attempt and then roll the entire improvement back. The repair now continues a bounded correction sequence while the blocker count stays monotonic, still restoring the original checkpoint if the set grows or cannot clear within the cap.
- **A late structure-repair regression no longer erases an independently verified improvement.** The bounded correction sequence could shrink nine arc blockers to one, then let its final attempt trade that residual for five and restore the entire pre-repair plan—discarding the proven one-blocker checkpoint. It now restores the best verified intermediate state, sends that partial improvement through the harsh foundation re-judge, and leaves the full arc gate dirty so the residual must still clear before beats. Model evidence follows the same transaction boundary: the retained repair runs remain provisional, while the regressive run is immediately scored as rejected; a fully reverted repair is also a rejection rather than a schema-invalid response.
- **Character-first planning now includes the cast's visual foundation.** The pre-arc character architect used to complete psychology and relationships while its response contract omitted physical description, silhouette, visual identity, and palette, so a graphic-novel series could settle its plot around characters the image pipeline still had to invent. Those identity-bearing fields now participate in completeness, prompt hashing, harsh foundation scoring, and repair; optional sheets such as props, expressions, gestures, and wardrobes are authored when the character's form supports them.
- **Character-first planning now finishes supporting cast bible cards too.** A character minted by series extraction could be omitted from foundation repair until their name appeared in the synopsis, and the repair allowlist dropped otherwise-useful profile fields such as pronouns, age, accent, likes/dislikes, mannerisms, and skills. Explicit `sourceSeriesId` ownership now keeps every series-linked character in exhaustive batches, and full narrative/visual profiles participate in completeness, hashing, repair, and harsh judging instead of stopping when only the lead framework is ready.
- **AI character expansion now finishes the whole visible bible card.** The expand action previously omitted physical description, personality, background, and outfits from both its response contract and no-clobber merge allowlist, so a technically successful run still left major UI sections empty. Those fields now fill alongside identity, motivation, framework, visual details, palettes, props, expressions, and gestures while every authored value remains protected.
- **Foundation judges now inspect the character designs they score.** Completed render fields were previously collapsed to the word `ready` in the judge context, so a harsh judge could only see that a value existed and then reasonably report that no anatomy, silhouette, palette, or visual grammar was available for comparison. The bounded context now carries the actual distinguishing details while still excluding unrelated universe assets.
- **Series Autopilot can pause without killing productive work.** The live control used to offer only Stop, which terminates the active provider run even when a long foundation judgment is doing useful work. **Pause safely** now records a graceful request, lets the active step and any provisional repair-verification transaction settle, then persists a resumable manual pause; **Stop now** remains available as the immediate emergency control.
- **Canon readiness now repairs manuscript-supported blanks before blocking art.** Autopilot's pre-render gate could identify a drawn character, place, or object with no description, but it immediately paused even though the Nouns workflow already had a safe fill-blanks-only service. The gate now runs that strict prose-grounded backfill for each affected issue, rechecks shared canon, and pauses only for locked nouns or visual facts the manuscript genuinely never established — never inventing unsupported design to force a pass.
- **Legacy canon prompts can be promoted into their missing description fields.** Universe expansion and promotion historically persisted image-ready `prompt` text while leaving the canonical `physicalDescription`/`description` blank, so the Cast/Places/Objects tabs and readiness gate disagreed with the renderer. A deterministic fill-blanks-only API now copies that already-authored text without an LLM call, preserving locks, IDs, kinds, prompts, and every existing asset.
- **Arc verification can now repair the per-character milestones it judges.** The verifier already read canonical per-character arcs, but its resolver could only edit the series arc, volumes, and issue synopses, so a contradiction in a character transition was impossible to close and repeated retries rewrote unrelated records instead. Finding-keyed character-arc patches now preserve character and transition IDs, merge only named fields, participate in regression rollback, and migrate existing prompt installations to the sparse contract.
- **Arc verification now inventories the whole plan before returning findings.** The verifier's checklist did not explicitly require a complete pass, so successive judges could reveal a new sample of latent geography, manifest, permission, clock, character-milestone, or issue-load contradictions after every otherwise-valid exact repair. The stage prompt now requires an exhaustive cross-record reconciliation, consolidation by root cause, and every evidence-backed high/medium finding in one response, reducing repair waterfalls without weakening the sparse-patch rollback guard.
- **Arc verification repairs long prose without rewriting the whole plan around one sentence.** A localized finding inside a volume synopsis previously forced the model to return the entire field, so a one-clause correction could rewrite more than 8,000 characters, introduce unrelated continuity failures, and be clipped at the storage limit. The resolver now emits bounded exact-match replacements for arc summaries, protagonist arcs, volume synopses, and ending hooks; missing, ambiguous, wholesale-long-field, and over-limit patches fail closed while legacy customized prompts keep their existing contract. Each prompt carries measured current/max/remaining field lengths so the replacement fits on its first attempt, and a rejected exact-only response is recorded as a no-op and retried without paying an independent judge to reread an unchanged plan. Because these patches are finding-keyed and bounded, an exhaustive later judge may expose unrelated latent blockers without the guard falsely blaming them on the patch and rewinding a correction that closed its target; legacy whole-field resolvers retain the stricter total-count guard. A graceful Pause requested during arc convergence now lands immediately after the active independent judgment instead of silently dispatching another repair/judge pair.
- **Completed CoS agents no longer strand a worktree because of their own completion marker.** The `.agent-done` sentinel is consumed before worktree cleanup, but Git still reported the untracked file as ordinary authored work and the safety gate preserved the otherwise-clean checkout with a high-priority warning. Cleanup now ignores only that runtime marker: sentinel-only trees are removed normally, while any real source change still preserves the worktree and is named in the warning.
- **A failed CoS task now diagnoses itself and comes back on its own.** A failing task used to pile up a queue of approval-gated tasks — the crash filed one, the provider failure filed another, repeated orphaning filed a third — and then, even after the cause was fixed, the original task sat `blocked` until someone un-blocked it by hand (or the 14-day reaper quietly retired it as stale). Both halves of that are now automatic. Every failure-driven investigation is filed through one producer, so they share a single approval policy, a single storm counter, and a single dedup fingerprint: unattended by default, held for you in exactly the two cases where another unattended agent would just repeat itself — the same cause was already investigated in the last 24 hours, or failures are cascading rather than isolated — and the task says which of the two it is. Completing an investigation, whether an agent finished it or you fixed the cause and ticked it off, then automatically retries every task that failure was blocking. Bounded at two automatic retries per task, after which the task stays blocked and says the retry loop gave up rather than still showing the original failure. A task you terminated or paused, one parked awaiting your arbitration, and one waiting on a repository path you have to fix are never revived behind your back.
- **The bundled local-LLM install catalog has been refreshed to the current model landscape.** Every suggested model was re-verified against the Ollama registry and the Hugging Face API, and the list is now built from what's current: Qwen3.5 / Qwen3.6, Gemma 4 (12B alongside the existing 26B/31B), Muse Glimmer, GLM-4.7 Flash, Granite 4.1, Ministral 3, Nemotron 3 Nano (including a 1M-context 30B), Olmo 3.1, LFM2.5, Qwen3-VL, MiniCPM-V 4.6, EmbeddingGemma, and the Ornith / North Mini Code / Devstral Small 2 coding tier. Models superseded by two generations were retired (Llama 3.1/3.2/3.3, Qwen2.5 + Qwen2.5-VL, Mistral 7B, Gemma 2, Phi-3, DeepSeek-R1 Distill, LLaVA 1.5, Code Llama, SmolLM2, Moondream) — but they still map exactly across backends, so migrating an older Ollama library to LM Studio doesn't degrade to a guessed name. Two entries were broken outright: the LM Studio repos for LLaVA 1.5 and Code Llama now 404. Ollama ids are checked for real local weights, because several headline 2026 models (Mistral Large 3, GLM-5.2, DeepSeek-V4, MiniMax-M3, Kimi K3) are published only as `:cloud` passthrough tags that would have installed nothing.
- **Local-model capability detection caught up with the models it now recommends.** Gemma 4 and Granite 4 report tool use (Gemma 3 genuinely couldn't, which is why the old rule stopped at Gemma 3), Gemma 4 reports vision, and Ornith / LFM2 / Olmo 3 / Muse Glimmer / North Mini Code / FunctionGemma are recognized as tool-callers — so they stop being hidden from agent and caption pickers on LM Studio, where PortOS has only the model id to go on. `embeddinggemma` is now correctly identified as an embedding model: it glues the marker onto the family name, slipped past the anchored `embedding` rule, and would otherwise have been offered as a chat model (the nomic-embed-text fallback bug). The editorial-model recommender learned the new families and now declines vision *specialists* (`*-VL`, `*V`, OCR) while still happily using a general model that can read images.
- **Series Autopilot now protects the author's originating story intent.** The Universe Builder starter idea is included in foundation-cache invalidation, rendered ahead of derived canon for the independent foundation judge, and supplied explicitly to arc generation with a hard rule against replacing its ontology, protagonists, or core story engine. Full-control runs still unlock derived world fields, but they keep the human-authored starter idea locked.
- **Character-first foundation repair gets a quality-first runtime.** Productive ensemble work may run for up to twelve hours instead of being discarded at ten minutes, matching the pipeline's other long-form editorial calls while operator cancellation remains available for a genuinely hung provider.
- **Episode synopsis revisions are now restorable.** Text-stage history snapshots preserve input-only stages as well as generated output, so regenerating an episode plan can no longer discard the prior synopsis merely because that planning stage stores its authored text in `input`.
- **Series Autopilot now validates the arc spine before spending on episodes.** A protected-intent checkpoint runs immediately after the macro arc, uses only canon demonstrably tied to the current series, honors the recommended volume count (including a single 12-issue volume), and blocks or auto-corrects an incompatible premise before issue generation. Existing empty issue placeholders are reused as an exact set so their ids, history, and visual links survive episode seeding.
- **Stopping Series Autopilot now stops the active AI run.** Direct arc, episode, foundation, correction, and fallback runs publish their concrete run ids to the conductor, so Stop no longer waits for a long provider call to finish. Runs History also exposes Stop for active rows.
- **Runs History safely displays structured model output.** Prompt and output endpoints are read as plain text, preventing valid JSON completions from crashing React when a run is expanded.
- **Arc auto-resolve keeps corrections field-scoped and within storage limits.** A resolver fixing one synopsis now omits unrelated volume fields instead of paraphrasing them, and its prompt carries explicit headroom below every persisted arc/volume string cap so a well-intended rewrite cannot be silently clipped into the next verification failure.
- **Arc verification preserves its best demonstrated draft.** Any auto-resolve pass that raises the total blocking-finding count now pauses immediately and restores the lowest-blocker arc snapshot seen in that gate, even when the verifier describes the added problems as newly surfaced findings. Equal-count rounds advance the checkpoint because narrower replacement findings can reflect real causal repairs; divergence and max-round exits therefore keep the latest verified best state instead of rewinding useful work or preserving whichever unverified rewrite happened to run last. Because that guard is deliberately blind to finding identity, it can fire on a round that genuinely closed the problem it was handed and merely exposed latent defects — so a pause that rewinds now also reports the discarded round's own findings, collapsed beneath the restored set, making the trade reviewable instead of leaving only a count behind. The same accounting covers the foundation structure repair, whose revert previously reduced the arc blockers that condemned the rewrite to a number in its pause message while the findings it listed were the unrelated dimension-level gaps.
- **Foundation repair distinguishes a deeper critique from a stalled rewrite.** When a harsh re-judge holds a dimension at the same coarse score but identifies a genuinely different underlying gap, that new layer receives its own bounded repair window. Fuzzy-matched paraphrases of the same problem still accrue toward the divergence guard, so the loop remains finite instead of pausing simply because one successful fix exposed the next weakness.
- **Foundation repairs must now earn their edits.** Before each world, character, structure, or craft repair, Series Autopilot checkpoints the complete foundation — universe prose and cast, series arcs and voice, volumes, and episode seeds. The next independent judge keeps a candidate only when its target dimension improves, or when a tied score exposes a genuinely new layer without lowering the weighted result. A repair that leaves its assigned problem unchanged or makes it worse is restored and verified immediately, then pauses with both the retained and discarded critiques instead of spending another long call on a worse baseline.
- **Foundation structure repairs cannot strand a newly contradictory arc.** Every judge-directed synopsis rewrite now snapshots the current plan, runs the specialized arc verifier, gives any new canon/location/timing blockers one bounded corrective pass, and restores the snapshot if that pass is still not clean or errors. The verifier uses the run's independent judge model while corrections stay on its creative model, and the extra calls are counted against the run's usage budget.
- **Continuing a video carries its prompt forward.** Continuing or extending a clip we generated now prefills the Video Gen prompt (and negative prompt) with the one that produced the source, instead of dropping you into an empty box. This covers both entry points: the **Continue** action on a video card/lightbox, and picking a prior render in Extend mode. Text you typed yourself is never overwritten — only a blank box or a value an earlier pick filled — and a clip we didn't generate (an import, or a legacy render with no stored prompt) leaves the field alone rather than clearing it. The style preset is dropped along with the prefill, since history stores the already-composed prompt and re-applying a preset would prefix it twice.
- **Subscription Usage cards now lay out in four quadrants.** The provider quota grid orders Claude, Antigravity, Codex, Grok — and because Codex and Grok typically report only a single weekly meter, they now share one grid cell stacked vertically instead of each stretching to a full-height card. Cards render at their natural height, so the Image Gen card floats into the fourth quadrant and the whole section fits above the fold on desktop.
- **Video LoRAs are no longer refused on MiniMax H3 by rule — they're gated on what the installed runner can actually do.** H3's DiT ships quantized, so an adapter can only be applied at render time from quantization metadata rather than fused into packed weights. PortOS previously rejected every H3 LoRA outright with LTX-shaped advice ("use an LTX-2.x model") that H3 users can't act on. A capability probe now asks the pinned checkout directly, and the answer flows through one path: the model payload, the Video Gen LoRA picker, the request gate, and the render argv. Until a capable build is pinned the rejection stands, but it names the real blocker and points at the runtime upgrade; the day one is pinned the picker opens with no code change. MiniMax H3 LoRAs also classify as their own video family on import, so they no longer land untagged or get mistaken for LTX adapters.
- **Code Review Defaults names all four model-pinnable CLI reviewers.** The panel's blurb still described only Codex and Claude as invoking their CLI directly, predating the Antigravity (#3728) and Grok (#3729) model pins, so it under-described the shipped `MODEL_CAPABLE_CLI_REVIEWERS` roster. Display text only — no behavior change.

## Fixed

- **A universe's chosen render engine now governs its cast, place, and object renders — not just batch runs.** Setting "This universe's default" on the Render tab persisted the pin correctly, and batch renders and character reference sheets obeyed it, but rendering a single reference from a Cast (or Places/Objects) card went to whatever the install-wide default resolved to — Codex on any Codex-enabled install — because those rows built their request from global image-gen settings and sent an explicit backend, which outranks a record pin server-side. Every render a universe queues now resolves the same ladder the batch path already used: the universe's own pin, then the "Universe Bible & canon renders" pin under Settings → Image Gen, then the install default — with the pinned model routed to the knob that backend actually reads. That covers the canon rows, clean plates, the base-style probe, the Story Builder characters step, and the pipeline Nouns stage, which previously ignored both pins. A pin naming a backend the install has since disabled falls through to the next rung instead of queueing a doomed job. Renders that arrive with no backend at all — from the API or an agent — resolve the owning universe's pin server-side too, from a pin-only read rather than a full record load.
- **An unset seed no longer renders the same image every time.** Blank seed and guidance fields were coerced with `Number('')`, which is `0` rather than "absent", so single-image renders shipped a hard `seed: 0` that the local runner honors as a fixed seed — repeat renders of one prompt came back identical, and `guidance: 0` disabled CFG. Blank now means absent; an explicitly typed `0` is still sent.
- **The prompt-drift baseline caught up with the exhaustive-arc-verification migration, un-reddening `main` again.** Migration 261 shipped a new `pipeline-arc-verify.md` and correctly recorded the prior default as an accepted-old hash, but the independent baseline in `scripts/setup-data-drift.test.js` still named the superseded hash as current — so every commit after it landed failed the drift sweep. The baseline now carries the shipped hash and lists the previous one among the accepted-old set. Same shape as the arc-resolve lapse below; the guard itself is unchanged and still fails when a migration ships a hash it doesn't export.
- **Foundation structure repair now keeps the safest verified checkpoint, not merely the one with the fewest findings.** The bounded verifier loop ranked candidates by raw blocker count, so a live repair that eliminated every high-severity authorization and climax failure was discarded because its deeper pass surfaced six medium/low follow-ups while an earlier four-finding checkpoint still contained two highs. Checkpoints are now ordered lexicographically by high, medium, low, then total count: one unresolved high can never be hidden by any number of polish findings, while equal-severity sets still prefer the smaller residual. The retained-progress message reports the complete severity profile so a partial repair is auditable.
- **The prompt-drift baseline caught up with the arc-resolve migration, un-reddening `main`.** Migration 254 shipped a new `pipeline-arc-resolve.md` and correctly recorded the prior default as an accepted-old hash, but the independent baseline in `scripts/setup-data-drift.test.js` still named the superseded hash as current — so the drift sweep disagreed with the migrations it mirrors and the suite failed on every commit after it landed. The baseline now carries the shipped hash and lists the previous one among the accepted-old set. The guard itself is unchanged and still fails when a migration ships a hash it doesn't export.
- **Body stats on the MeatSpace Overview card no longer show raw float precision.** A unit-converted weight rendered every binary digit it carried (the shape `170.35000000000002 lbs`), blowing out the tile's line and implying precision the measurement never had. Weight, body fat, lean mass, and the body-composition chart's tooltip now share `formatWeight` / `formatPercent` from the client formatters, which round to one decimal, drop trailing zeros, and render a dash for a missing reading instead of a coerced zero.
- **Labels floating over 3D and Three.js previews now follow the active theme.** The status bar on a generating Three.js model read as dark green text on a near-black slab — that chrome was written as a fixed black scrim with white text, and on a light theme the white text is remapped to the theme's dark ink while the black scrim stays black. Overlay chrome across the 3D and Three.js surfaces (the generation status bar, the preview's background/explode and part-selection panels, the orbit hint and articulation badge, the mesh viewer's display-settings button, and the "Change image" labels on both pickers) now takes its surface and ink from the theme itself, so it matches the page and stays legible over a dark canvas, a light one, or a photograph.
- **PortOS no longer boots to a blank white page when it can't reach the public internet.** The app shell pulled Inter and IBM Plex Mono from `fonts.googleapis.com` as a render-blocking stylesheet, so on any install with no route to Google — no WAN, a DNS sinkhole, an outbound firewall — the browser held the first paint until that request timed out. Measured on a live install: ~60 seconds of blank white page on every single navigation, with no console error to explain it. The stylesheet now loads non-blocking, so first paint no longer waits on a third-party host. Nothing regresses when the fonts are reachable, and a guard suite pins the shell so no future request can make boot depend on a cross-origin host again.
- **One over-long character-arc field no longer bricks every save on the Series settings page.** The arc editor's inputs carried no length caps, while the PATCH route enforces its limits with Zod, and Save re-sends the entire arc list every time — so a single field over its cap rejected the **whole** series PATCH (name, logline, premise, style guide and all) and kept rejecting it on every subsequent attempt. The inputs now cap at the server's limits, and a parity suite fails if the mirrored caps ever drift.
- **LoRA cards no longer show a permanently broken thumbnail for video previews.** Civitai's preview picker only sorted by explicitness rating, so a version whose least-explicit entry was a video clip stored an `.mp4` URL that the card then rendered as an image. Videos are now skipped when picking a preview, and a version with no still image falls back to the placeholder. Applied on read as well as on install, so already-installed LoRAs recover without a reinstall.
- **Brain Memory and Media History no longer paint every record at once.** A live install with ~1.5k imported ChatGPT memories was mounting full Markdown trees for every card (~180k DOM nodes), and Media History mounted ~1.8k gallery cards with images in one grid — both tabs froze on open. Memory now shows a plain teaser for imported transcripts and both lists use a progressive "Show more" window so search still covers the full set while only a page of cards mounts.
- **The pre-episode arc-spine check now resolves at the altitude it judged at.** That checkpoint verifies the arc spine with the episode lineup deliberately hidden, but its auto-resolver was still handed the full episode lineup and told to fix contradictions there — so it answered spine findings by rewriting episode synopses the gate had never read, which couldn't close what was flagged and doubled the blocker count on the next pass. Spine rounds now render the resolver the same episode-empty plan the verifier saw and discard any episode edits it returns anyway.
- **Arc rollback now rejects equal-count severity regressions.** A resolver could trade a medium continuity gap for a new high-severity canon violation while the total finding count stayed identical, and an unchanged count was always accepted as a potentially narrower restatement. Equal-count candidates are now ordered by severity before they can replace the checkpoint, so a severity escalation is treated as a regression and reverted.
- **A reverted arc auto-resolve round no longer ends the whole run on its first bad attempt.** The revert still happens exactly as before; what follows it is now one bounded corrective pass, telling the resolver what its own discarded attempt just produced as the failure mode to avoid. Only when that second attempt also regresses does the gate pause for review.
- **A provider outage no longer hands a CoS task's model pin to a provider that can't run it.** A task pinned to one provider's model correctly fell back to a different provider on an outage, but carried the original provider's model id along, so every retry died in ~1.5s against a model id the new provider had never heard of. A fallback swap now drops the pin back to the new provider's own default unless that provider actually lists it.
- **The Claude CLI's own model rejection is now a recognized, actionable failure.** "There's an issue with the selected model" — printed at CLI startup before any API call — previously landed in an `unknown` failure bucket that escalated to an investigation task, burning all retries against a model id that could never work. It now classifies as a config/environment issue where a model correction belongs.
- **Stopping the CoS Runner no longer burns through queued agent tasks.** Turning off the separate runner app used to charge a retry (or, on the TUI path, park a task for a human) for every task that tried to dispatch while it was down. Tasks now hold and re-dispatch automatically the moment the runner reconnects, with the reconnect debounced and capped so neither a long outage nor a crash-looping runner is expensive.
- **The Antigravity account-eligibility banner no longer kills an agy run before it can start.** A routine part of the CLI's sign-in handshake was being treated as an immediate fatal signal, killing the session before the model was ever asked for a token. The signal is now marked self-clearing: the session holds for up to 60 seconds and lets the run continue the moment the model starts generating.
- **A foundation repair that was correctly rolled back no longer reports the rollback as corrupted.** Undoing a repair is itself a content change, and the write path re-stamps a timestamp it owns on every entry it restores — the verification was comparing that server-owned stamp byte-for-byte, so every faithful rollback failed its own check. The comparison now ignores the fields the write path owns while still comparing all authored content.
- **The rollback comparison now ignores write-path-owned fields on every kind of canon entry, not just characters.** The character-only fix above would have quietly reintroduced the same bogus failure for worldbuilding canon (places, objects); the comparison now covers every canon array the story bible defines.
- **A managed app pinned to a self-hosted GitHub/GitLab is now reconciled the same way its Issues tab lists it.** A background reconciler was classifying an app's forge from its hostname alone, so it silently skipped scanning any self-hosted Enterprise/GitLab instance that the Issues tab correctly recognized via its explicit pin. Both paths now share one resolver.
- **Stopping an autonomous run no longer reports it as a crash and files a bug for it.** Cancelling a Series Autopilot run, stopping the LLM call it's sitting on, or restarting PortOS mid-run used to be misclassified as a genuine failure if it interrupted a step rather than landing between steps — leaving the series in an unresumable `error` state and filing a bogus "the run failed" investigation task. An interrupted step now ends the run the same resumable way a between-steps cancel does.
- **A CoS runner that is briefly unreachable no longer blocks the task for a human.** A momentary spawn failure — the runner restarting, a transient refusal — used to immediately block the task and file an investigation with escalation advice that didn't apply. It now retries first and only blocks after the retry budget is spent, mirroring how the direct-CLI runner path already handled this.
- **Insights overview cards now carry the step they describe instead of naming a control that isn't on the screen.** Empty-state prose referencing "Click Refresh" or a prerequisite with nowhere to complete it now ends in a button that does the thing directly.
- **Settings → Backup now keeps Save and Run Backup Now in reach.** A long catalog of default-exclusion toggles pushed both save actions below the fold with no indication anything was unsaved. The catalog now collapses behind a disclosure, and Save/Run Backup Now sit in a sticky bar that also tracks the Enabled toggle and schedule as unsaved edits (previously only the destination path did, so a schedule change could silently run against the old saved value).
- **The "install out of sync" and "update available" notices no longer sit on top of the screen you're using.** Both were permanent corner toasts that, on mobile, covered the Ask composer's Send button, the Add Peer form, and the process list — and neither ever timed out. They're now inline banners in the app chrome that push the page down instead of covering it.
- **The Timeline's seven backfill importers no longer outrank the day you came to look at.** Every one-time import panel rendered at full width above the content, taking up the whole top half of the viewport before a single event appeared. They now live behind one "Import history" toggle.
- **System Health alerts now name the page that fixes them.** Every warning used to be a bare statement with no link; each alert now carries a remediation link to the relevant settings page.
- **Tribe now opens on the people who need a touch, and the "Needs Care" number is a control.** The page used to lead with pure summary tiles before any person appeared, pushing every actionable Touch button below the fold. The Care Queue is now the landing tab, and the summary tiles became filter buttons with a shareable deep link.
- **OpenClaw is a chat screen again instead of the Settings tab strip with a chat under it.** The full 22-item settings tab bar rendered above the chat's own header, pushing the composer and Send button below the fold on mobile. The settings chrome collapsed into a disclosure and the conversation now owns the width.
- **Arc verification no longer reports a phantom "no pilot or finale" on a volume that has both.** The plan snapshot handed to the verifier never included the `arcRole` field, so every volume looked role-less regardless of how it was actually laid out — and because the foundation gate reverts a whole structure rewrite over any remaining blocker, this phantom finding alone could sink a repair that had genuinely fixed everything else. The snapshot now carries the field.
- **A URL that doesn't match a page now says so instead of quietly depositing you on the Dashboard.** Unknown routes previously redirected silently to the Dashboard, indistinguishable from losing your navigation. They now render a 404 page naming the path that didn't match, with links back and a reminder that ⌘K searches every page.
- **A character repair that objectively filled the blank cast fields is no longer thrown away because the judge scored it a tie.** A repair that authored five blank visual fields for five characters was reverted in full because the judge's overall score held steady while unrelated worldbuilding drifted slightly. The gate now takes a second, LLM-free opinion for tied character repairs: it counts blank fields before and after, and keeps work that measurably reduced them.
- **A local video render now tells you how long it has left, once your machine has rendered something comparable.** Each completed render now records its wall-clock time and shape, and a new job estimates its remaining time from that history instead of showing only a step counter.
- **A video LoRA in the wrong key layout is now refused with the reason instead of quietly rendering an un-LoRA'd clip.** Downloaded LoRAs ship in several incompatible file layouts, and only one is compatible with the video loader — a mismatched one previously burned the full render time and came back looking like the LoRA was never applied. PortOS now classifies the layout at install time and refuses an incompatible one up front, naming what to use instead.
- **A generated Three.js model is now checked for parts modelled inside each other.** A new gate compares every part's reconstructed 3D placement against every other part's, flagging one part fully swallowed by another — a defect invisible from the model's own hero camera and only apparent once you orbit or explode the assembly.
- **A resumed arc verification no longer forgets why its last rewrite was rejected.** A fresh Resume discarded the record of what a prior rejected rewrite got wrong, making the resumed run liable to repeat the same bad trade. The rejected evidence is now carried into every resume.
- **A fresh install's prompt migrations stopped silently skipping the character-foundation upgrades they exist to apply.** Several migrations that re-shipped the same stage prompts left earlier migrations targeting those files pointed at a superseded body, so a fresh install classified today's shipped prompt as "user-customized" and silently skipped upgrading it. A repo-wide guard now sweeps every migration in one pass to catch this class of drift going forward.
- **A server test run no longer drops fixture directories into the checkout.** Several test suites rooted scratch directories at the working directory instead of the OS temp dir, so a killed test worker could leave untracked files behind — one made it into a claim branch once. They now allocate a proper per-test temp directory.
- **A prompt change that skips the drift baseline no longer reddens `main` with an unreadable failure.** The independent drift-baseline assertion previously reported only an opaque object-diff, misleading three separate PRs into treating an inherited `main` failure as their own regression. It now names the drifted files with their before/after hashes and the fix to apply.
- **PortOS now renders its intended typography with no route to the public internet, because the fonts ship with it.** An earlier fix stopped the Google Fonts stylesheet from blocking first paint, but the fonts still never arrived on an offline install — meaning five of PortOS's themes were silently rendering in a system fallback font. Both font families are now vendored and bundled directly, removing a third-party network request from every boot.
- **A generated Three.js model's materials are now checked against the substance they're named for.** The existing schema allowed a wooden crate to validate as fully metallic or a window to validate as fully opaque glass. A new advisory gate flags PBR values that don't match what a material's own name implies (metal, wood, glass, fabric, and more), without ever clamping a deliberately stylized choice.
- **Stitched and re-encoded video renders now carry BT.709 color tags, so they stop decoding washed-out.** Every ffmpeg re-encode step in video generation wrote output with no color metadata, leaving players to guess (and often guess wrong). All affected renders now tag color space explicitly, verified to actually stick on the ffmpeg version PortOS runs.
- **The Digital Twin's 19 sections are grouped now, instead of one 19-wide tab strip you had to read end to end.** The flat strip carried every section with no inferable order, and on mobile pushed the twin's own action buttons below the fold. Sections now collapse into five named groups (Profile, Sources, Assessment, Presence, Legacy), with existing deep links, ⌘K entries, and voice navigation targets unchanged.
- **An arc verification no longer forgets a rejected rewrite one round after it reverted it.** Discarded blocker evidence was only carried into the single corrective retry that immediately followed a rollback; if that retry also failed, the next ordinary resolve forgot the history and could re-author the exact rewrite that had just been thrown away. Every discarded set in a run is now accumulated and passed to every later resolve attempt in that gate.
- **That rejected-rewrite evidence now survives the pause, and the isolation pass banks its own.** A run that reverted two different rewrites before pausing previously kept only the most recent one across a Resume, and the per-finding isolation pass never recorded its own rejected patches at all. Both gaps are closed — the full discard history now persists across a pause, and isolation tracks its own rejections per target.
- **The foundation gate now remembers every repair it rejected for a dimension, not just the last one.** The foundation gate's rejection memory only kept the single most-recent rejected repair per dimension, unlike the arc gate's full history — so a dimension that rejected two different repairs only warned the third attempt about the second. Both gates now share the same accumulating-history model.
- **An "isolated" arc repair now has to actually be one small edit.** The escalation that resolves one finding at a time to break a repeated-regression loop wasn't actually constraining the edit size — a single-finding response could still rewrite the whole plan and regress exactly like the pass it escalated from. The resolver now has an explicit isolated mode that the server rejects unless it is genuinely one causal, bounded patch.
- **A character-arc beat is no longer clipped mid-word, which was enough on its own to stall an arc verification.** Character-arc text fields were capped with a hard character slice that could end mid-sentence, and the next verification round read the fragment as an unresolvable authoring gap. These fields now back off to the last complete sentence or word instead of cutting mid-word.
- **An arc rollback now reverts only what the round it is undoing actually wrote.** A rejected round's rollback was diffing the entire store against its pre-round snapshot and reverting every difference found, even changes another process made concurrently while the multi-call verification was running. The resolver now returns an exact manifest of what it wrote, and rollback restores only entries on that manifest whose value hasn't since been overwritten by something else.
